## 보드 구성

1. 사용자와 기본 유스케이스
2. 대메뉴·소메뉴·화면 ID
3. 대시보드·차량 상세 흐름
4. 운행이력 화면별 흐름
5. 서비스 화면별 흐름
6. 리포트·지도·관리 기능 흐름

참여 요소는 `사용자`, `화면 입력`, `조회 상태`, `API 요청`, `응답 데이터`, `화면 상태`, `다음 이동`처럼 전체 이름으로 표기합니다. U·S·C·A·R 같은 약어는 사용하지 않습니다.

## 공통 프로세스 참여자 표기

기존 `U · S · C · A · R` 약어는 아래 전체 명칭으로 교체합니다.

1. 사용자
2. 화면 입력·선택 상태
3. 프론트 화면·상태 제어
4. API 요청·응답 처리
5. 데이터 응답·저장소

각 화면 프로세스에는 `진입 조건 → 조회 대상 선택 → 페이지 변수 생성 → API 요청 → 응답·권한 확인 → 화면 상태 → 다음 이동·조치` 순서를 표시합니다.

## 페이지 변수 전달 구조

| 변수 | 생성 위치 | 전달·수신 | 검증 |
|---|---|---|---|
| service | 플릿·딜러 진입 URL·로그인 서비스 | 라우터·메뉴 | fleet/dealer 허용값 |
| locale | 사용자 설정·URL 언어 구간 | i18n 저장소·API | BCP 47 표준화 |
| companyId | 상단 업체 선택 | 라우트·상태 저장소·API | 사용자 접근 업체 서버 재검증 |
| groupId | 업체 하위 그룹 선택 | 라우트·상태 저장소·API | companyId 변경 시 초기화 |
| equipmentId | 차량 목록·상세 선택 | 라우트 path·API | 업체·그룹 소속과 권한 재검증 |
| periodTypeCode | 일·주·월·사용자설정 | 화면 상태·API | 날짜 직접 수정 시 custom 전환 |
| startDate / endDate | 기간 계산·사용자 입력 | API query | 지역 시간 경계·서버 허용 범위 확인 |
| pageNo / pageSize / sortCol | 목록 조작 | API query | 서버 허용 정렬 컬럼만 사용 |

업체 변경 시 그룹·차량 값을 초기화하고, 그룹 변경 시 차량 값을 다시 검증합니다. URL에 ID가 있다는 사실은 권한 증명이 아니므로 서버가 인증 사용자 범위와 교차 확인해야 합니다.

## 메뉴 권한·다국어 처리

- 메뉴 진입: 서비스·역할·메뉴 권한 확인
- 조회 범위: companyId·groupId·equipmentId와 사용자 조직 범위 교차 검증
- 필드 노출: 플릿/딜러별 서버 DTO에서 허용 필드만 반환
- 조치 권한: `menu.view`, `maintenance.detail.view`, `supply.reset`, `document.download`처럼 조회와 실행 권한 분리
- 공통 문구: i18n 번역 키 사용
- 업무 코드: BCP 47 locale 기반 번역 리소스 사용
- 날짜·시간: UTC 저장 후 사용자 IANA timezone으로 표시
- 숫자·단위: 기준 값과 unitCode를 분리하고 화면에서 지역 단위로 변환

## 데이터 구조 진단 연결

개발 아틀라스의 `데이터 구조 진단` 페이지에서 다음 내용을 한 페이지로 연결합니다.

1. 요구사항별 현재 테이블·필드
2. 현재 구현 가능 범위와 데이터 공백
3. 문제점과 사용자·개발 영향
4. 해결안과 확인 질문
5. 현재 테이블 구조의 공통 문제
6. 글로벌 목표 데이터 구조와 적용 순서

`R-SVC-003`은 31일 제한으로 확정하지 않습니다. 확인 질문은 `사용자설정 조회를 실제 업무상 어느 기간까지 허용할지, 서버 성능·데이터량·응답시간 기준과 함께 확인 필요`로 표기합니다.
