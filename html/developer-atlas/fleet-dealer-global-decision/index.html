04 · SOLUTION / CORE DDL

차량 원장과 조직 관계 분리, 관계 유형·유효기간 필드 추가

적용 방안

조직 경계와 조직 원장

CREATE TABLE TENANT (
  tenant_id VARCHAR(40) PRIMARY KEY,
  tenant_code VARCHAR(40) NOT NULL UNIQUE,
  country_code CHAR(2) NOT NULL,
  default_locale VARCHAR(10) NOT NULL,
  timezone_id VARCHAR(50) NOT NULL,
  unit_system VARCHAR(12) NOT NULL,
  data_region VARCHAR(30) NOT NULL,
  status VARCHAR(20) NOT NULL
);

CREATE TABLE ORGANIZATION (
  organization_id VARCHAR(40) PRIMARY KEY,
  tenant_id VARCHAR(40) NOT NULL,
  parent_organization_id VARCHAR(40),
  organization_type VARCHAR(20) NOT NULL,
  organization_name VARCHAR(200) NOT NULL,
  status VARCHAR(20) NOT NULL,
  FOREIGN KEY (tenant_id) REFERENCES TENANT(tenant_id)
);

차량–조직 관계와 사용자 권한

CREATE TABLE EQUIPMENT_ORGANIZATION_RELATION (
  relation_id BIGINT PRIMARY KEY,
  tenant_id VARCHAR(40) NOT NULL,
  equipment_id VARCHAR(40) NOT NULL,
  organization_id VARCHAR(40) NOT NULL,
  relation_type VARCHAR(20) NOT NULL,
  valid_from TIMESTAMP NOT NULL,
  valid_to TIMESTAMP,
  status VARCHAR(20) NOT NULL,
  source_table VARCHAR(50), source_key VARCHAR(100),
  created_at TIMESTAMP NOT NULL, created_by VARCHAR(40)
);

CREATE TABLE USER_ORGANIZATION_ROLE (
  user_id VARCHAR(40) NOT NULL,
  organization_id VARCHAR(40) NOT NULL,
  role_code VARCHAR(40) NOT NULL,
  valid_from TIMESTAMP NOT NULL, valid_to TIMESTAMP,
  PRIMARY KEY(user_id, organization_id, role_code, valid_from)
);

구현 기준 텔레메트리·운행·배터리·정비 원천 테이블 유지. 신규 구조는 관계·권한·이력 관리에 사용. ID 생성·TIMESTAMP 문법은 적용 DBMS 기준으로 조정.

06 · GLOBAL AMPLIFICATION

국가 확장 시 추가되는 권한·시간·단위·데이터 저장 기준

Tenant / Region

국가·법인별 데이터 경계가 없으면 동일 ID 충돌과 다른 지역 데이터 조회 가능성

조직 유형

본사·딜러·지점·서비스센터·고객사의 계층과 역할을 한 필드로 표현 불가

시간 기준

UTC 저장, 사용자 시간대, 주 시작일, 일·월 집계 기준 결정 필요

다국어

코드와 표시 문구를 분리하지 않으면 국가별 설명·에러 안내 관리 불가

단위

km/mile, L/gallon, ℃/℉의 원천값과 표시값 분리 필요

데이터 거주

개인·위치 데이터의 저장 지역과 보존 기간을 tenant 정책으로 관리 필요

발생 가능 문제관계 기준이 분리되지 않으면 다른 국가·법인 고객 차량이 조회 범위에 포함될 가능성

08 · SOLUTION / GLOBAL CONTEXT

공통 요청에 tenant·시간대·언어·단위 정보 포함

현행 문제

  • 업체 ID만으로 국가·법인 경계 식별 불가
  • 일·주·월 집계가 사용자 시간대와 분리되지 않음
  • 코드·표시 문구·단위가 화면마다 해석될 가능성
  • 데이터 거주 지역과 접근 범위 연결 없음
→

확정 해결안

  • tenantId로 데이터 경계 선확정
  • 원천 시간 UTC 저장, 집계 경계는 timezone 적용
  • 원천 단위 유지, API 응답에서 표시 단위 변환
  • 코드는 고정하고 문구는 locale 리소스로 분리
공통 요청tenantId · serviceType · organizationId · equipmentId? · period · locale · timezone · unitSystem
공통 응답context · permissions · data · meta{generatedAt, timezone, unitSystem, locale} · warnings · page

프론트 규칙 화면에서 권한과 단위를 재해석하지 않음. 백엔드가 확정한 context와 변환된 표시값을 렌더링.

15 · SOLUTION / ACCESS SCOPE

모든 페이지에 공통 접근 가능 차량 조회 모듈 적용

서비스별 허용 관계

  • 플릿: OWNER · OPERATOR · VIEWER
  • 딜러: SELLER · SERVICE
  • 사용자 역할의 유효기간과 조직 범위 선검증
  • 차량 ID 직접 호출도 같은 범위로 재검증

화면별 COMPANY_ID 조합과 대량 IN 목록 제거.

공통 접근 범위 SQL

WITH authorized_org AS (
  SELECT uor.organization_id
  FROM user_organization_role uor
  WHERE uor.user_id = :userId
    AND :asOf >= uor.valid_from
    AND (uor.valid_to IS NULL OR :asOf < uor.valid_to)
), accessible_equipment AS (
  SELECT DISTINCT r.equipment_id
  FROM equipment_organization_relation r
  JOIN authorized_org ao ON ao.organization_id = r.organization_id
  WHERE r.tenant_id = :tenantId
    AND r.organization_id = COALESCE(:organizationId, r.organization_id)
    AND r.relation_type IN (:allowedRelationTypes)
    AND r.status = 'ACTIVE'
    AND :asOf >= r.valid_from
    AND (r.valid_to IS NULL OR :asOf < r.valid_to)
)
SELECT e.* FROM tb_equipment e
JOIN accessible_equipment a ON a.equipment_id = e.equipment_id
WHERE (:equipmentId IS NULL OR e.equipment_id = :equipmentId);

현행 문제 / 적용

KPI와 각 목록이 서로 다른 조건을 쓰면 0건 표시와 실제 목록 건수가 불일치.

  • 정비·소모품·차량에러만 집계
  • 배터리 에러는 차량에러 포함

페이지 SQL

SELECT
 (SELECT COUNT(*) FROM tb_service_repair_result r
   JOIN accessible_equipment a ON a.equipment_id=r.equnr)
   maintenanceCount,
 (SELECT COUNT(*) FROM tb_service_schedule s
   JOIN accessible_equipment a ON a.equipment_id=s.equipment_id
   WHERE s.use_yn='Y' AND s.exchange_remain_sec<=0)
   supplyDueCount,
 (SELECT COUNT(*) FROM fault_event f
   JOIN accessible_equipment a ON a.equipment_id=f.equipment_id
   WHERE f.status='OPEN') faultCount;

SELECT u.user_id,u.user_name,
       uor.organization_id,uor.role_code,
       u.locale_code,u.timezone_id,u.use_yn
FROM tb_user u
JOIN user_organization_role uor ON uor.user_id=u.user_id
JOIN organization o ON o.organization_id=uor.organization_id
WHERE o.tenant_id=:tenantId
  AND uor.organization_id=:organizationId
  AND :asOf>=uor.valid_from
  AND (uor.valid_to IS NULL OR :asOf<uor.valid_to);
