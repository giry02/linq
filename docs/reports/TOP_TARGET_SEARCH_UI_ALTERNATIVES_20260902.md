# MACHINE IQ 상단 조회 대상 검색 UI 대안 리포트

- 작성일: 2026-09-02
- 대상 화면: 플릿 · 운행이력 · 요약정보 3안
- 검토 범위: 업체 → 그룹 → 분류 → 차량 선택과 차량 상세검색
- 기준 화면: 현재 로컬 HTML 및 GitHub Pages 프로토타입

## 1. 결론

현재 단계에서는 기존 화면 변화가 가장 적은 `4단계 연속 풀다운`을 유지하는 것이 적절하다. 라벨과 선택값을 한 줄에 두고, 선택값 길이에 따라 각 풀다운 폭이 변하도록 하며, 우측 상세검색 버튼은 고정한다.

조회 대상 종류가 더 늘어나거나 차량 수가 많아져 풀다운 탐색이 느려지면 `조회 대상 팝업형 통합 검색`으로 전환하는 방안을 권장한다. 상단에는 선택 결과만 짧게 표시하고, 업체·그룹·분류·차량 검색과 선택은 하나의 팝업에서 처리하는 방식이다.

## 2. 현재 방식의 장점과 한계

### 장점

- 업체 → 그룹 → 분류 → 차량의 선택 순서가 화면에서 바로 보인다.
- 기존 화면과 구조적 차이가 작아 사용자 학습 부담이 낮다.
- 각 단계의 차량 수를 즉시 비교할 수 있다.
- 서버 API가 단계별 목록을 제공할 경우 연결 구조가 단순하다.

### 한계

- 업체명과 차량번호가 길면 상단 가로 공간을 많이 사용한다.
- 다섯 번째 이상의 조회 조건을 추가하기 어렵다.
- 업체와 차량 수가 많아지면 기본 HTML 풀다운만으로 검색 속도가 떨어진다.
- 선택 단계가 많을수록 이전 단계로 돌아가 값을 바꾸는 횟수가 늘어난다.

## 3. 대안 비교

| 안 | 구성 | 장점 | 단점 | 적합한 상황 |
|---|---|---|---|---|
| A. 4단계 연속 풀다운 | 업체·그룹·분류·차량을 상단 한 줄에 배치 | 기존 화면 유지, 단계 관계가 명확, 구현 난이도 낮음 | 조건이 늘어나면 공간 부족 | 현재 프로토타입과 단기 적용 |
| B. 통합 자동완성 검색 | 하나의 검색창에서 업체·그룹·분류·차량을 모두 검색 | 빠른 직접 검색, 상단 공간 최소화 | 계층 관계와 각 단계 카운트가 약하게 보임 | 사용자가 정확한 이름이나 차량번호를 아는 경우 |
| C. 조회 대상 팝업형 통합 검색 | 상단 버튼을 누르면 검색창과 4단계 목록을 가진 팝업 표시 | 조건 추가가 쉽고 긴 명칭 처리에 유리, 검색과 계층 탐색 동시 제공 | 팝업을 한 번 열어야 하며 구현 범위가 큼 | 조건·차량 수가 계속 증가하는 운영 화면 |
| D. 회사 고정 + 상세 필터 팝업 | 업체만 상단에 두고 그룹·분류·차량은 필터 팝업에 배치 | 주요 업체 선택은 빠르고 상단이 단순함 | 업체 외 조건이 숨겨져 현재 범위 파악이 느림 | 업체 전환이 대부분이고 세부 필터 사용 빈도가 낮은 경우 |

## 4. 권장 팝업형 구조

중장기 권장안은 C안이다.

1. 상단에는 `조회 대상` 버튼과 현재 선택 결과를 표시한다.
2. 버튼을 누르면 기존 화면 스타일의 흰색 팝업을 연다.
3. 팝업 상단에는 업체명·그룹명·분류명·차량번호를 모두 찾는 통합 검색창을 둔다.
4. 검색창 아래에는 업체, 그룹, 분류, 차량을 좌→우 4열로 배치한다.
5. 상위 항목을 선택하면 오른쪽 하위 목록과 카운트가 즉시 갱신된다.
6. 하단에는 `초기화`, `적용` 버튼을 둔다.
7. 적용 후 상단에는 `업체명 · 그룹명 · 분류명 · N대`처럼 선택 결과만 표시한다.
8. 차량번호를 직접 검색해 선택한 경우에는 선택 차량번호를 가장 우선해 표시한다.

이 구조는 상단 폭을 고정하면서도 향후 지역, 딜러, 상태 같은 조회 조건을 추가할 수 있다.

## 5. 현행 4단계 풀다운 유지 시 개선 기준

- 라벨은 14px, 선택값은 12~13px로 구분한다.
- 선택값 길이에 따라 풀다운 폭이 변하되 단계별 최소·최대 폭을 둔다.
- 각 풀다운 사이에는 최소 8px 이상의 시각적 간격을 둔다.
- 차량 수는 선택값 안의 `· N대` 형식으로 유지한다.
- 업체명과 차량번호는 말줄임 없이 표시하고, 가변 폭 상한에 도달할 때만 브라우저 기본 선택 목록에서 전체 값을 확인하게 한다.
- 현재 조회 배지는 내용 길이에 따라 늘어나며 임의 고정 폭으로 자르지 않는다.
- 상세검색 버튼은 우측 기준선을 유지하고 모든 입력과 같은 36px 높이를 사용한다.
- 목록이 20개를 넘는 업체·차량 풀다운에는 검색 가능한 콤보박스 적용을 검토한다.

## 6. 권장 적용 순서

1. 현재 4단계 가변 풀다운을 요구사항 검토 화면에 적용한다.
2. 실제 API의 업체·그룹·분류·차량 데이터와 카운트를 연결한다.
3. 업체 또는 차량 목록이 20개를 넘는지 사용 데이터를 확인한다.
4. 탐색 시간이 길거나 조건 추가 요구가 발생하면 팝업형 통합 검색 프로토타입을 별도로 제작한다.
5. 두 안을 동일 데이터로 비교한 뒤 운영 화면 적용 방식을 결정한다.

## 7. 결정 제안

- 단기: 현재 4단계 가변 풀다운 유지
- 중기: 업체·차량 목록에 검색 가능한 콤보박스 적용
- 장기: 조회 대상 팝업형 통합 검색으로 확장

팝업형 전환은 현재 HTML을 전면 재설계할 필요 없이 상단 선택기 영역만 교체하는 범위로 진행할 수 있다.
